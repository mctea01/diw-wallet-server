# Agent notes

- Production server for DIW MY WALLET; design and milestones in docs/DESIGN.md. Keep it independent: protocol code comes from the wallet's `core` (submodule `wallet/`, composite build), never copied or reimplemented here.
- Endpoints must stay wire-compatible with what the wallet app calls (see docs/DESIGN.md section 3).
- Build: JDK 21 and Android SDK (`ANDROID_HOME`); `DIW_ZK_NATIVE=skip` when no native proof backend is needed (the zktls host needs `DIW_ZK_NATIVE=require DIW_ZK_FEATURES=tlsn`). `./gradlew test installDist distTar`; on linux-x86_64 the distribution always carries a jlink runtime in `runtime/` (task `runtimeImage`), which the image uses; other hosts skip it.
- The start script prefers `APP_HOME/runtime` when JAVA_HOME is unset; the image and the systemd unit use AppCDS via `JDK_JAVA_OPTIONS`. Keep `runtimeModules` in build.gradle.kts in step with `jdeps --print-module-deps` when dependencies change.
- Settings: every key lives in `ConfigKeys.kt`; every deployment reads the same `DIW_<KEY>=value` file and only sets `DIW_PLATFORM` (platform defaults). After adding or changing a key, regenerate `deploy/server.conf.example` with `diw-server config-template` (ConfigTest compares them and checks the deploy files name only known keys). `settingsSha256` covers non-deployment, non-secret values.
- Deploy files: deploy/caddy, deploy/systemd, deploy/cloudrun, deploy/cloudflare (Worker routing to one container instance, SERVER_CONF passed as DIW_CONFIG_TEXT; `npx tsc --noEmit` there checks it). Platforms without a persistent disk default to `signing_generate=false` and take keys from the settings file (`DIW_SIGNING_KEY_PEM`, `\n` for line breaks).
- Server engine is Ktor CIO (the only engine GraalVM native image supports). Native build: GraalVM 25 (`GRAALVM_HOME`, `./gradlew nativeCompile`); regenerate reachability metadata with `tools/native-metadata.sh` (needs GraalVM 21 for the agent) after adding routes, serializers or dependencies; `./gradlew test -Pdiw.nativeServer=build/native/nativeCompile/diw-server` runs the zkTLS end-to-end test against the native binary.
- `federation`: OpenID Federation Entity Configuration (`Federation.kt`); the wallet resolves it with core's `FederationResolver` under entity type `diw_wallet_server`, so keep metadata names in step with the wallet's `ServerModel`.
- Code, comments and commit messages in English, no emoji; user-facing docs in Traditional Chinese.
- `twfido` signs with this server's mobile citizen certificate SP account through the wallet's `TwFidoClient`; ID numbers, hints and signed bytes stay in memory and are never logged or echoed back.
- `oprf` answers blinded OPRF queries for zkPassport salted identifiers with the key from `oprf_key` (a secret, never in the APK or logs); it needs `oprf` in the native library and only ever sees blinded points.
- Sized for a 1 GB host: keep memory bounded, never log request contents, disclosed values, tokens or keys.
- Agents cannot push `.github/workflows/`; propose workflow changes as a full file for the user to paste into .github/workflows/docker-image.yml.
- Tests use `runBlocking<Unit>` / `testApplication`; a test function must return Unit or JUnit skips it.
